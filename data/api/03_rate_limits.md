# Rate limits API FinPay

## Базовые лимиты
- 100 запросов в секунду на аккаунт для операций чтения (`GET`).
- 30 запросов в секунду на аккаунт для операций создания/изменения
  (`POST`/`PUT`/`DELETE`).
- Лимиты считаются по скользящему окну в 1 секунду, а не по фиксированным
  интервалам.

## Заголовки лимитов в ответе
Каждый ответ содержит заголовки `X-RateLimit-Limit` (лимит),
`X-RateLimit-Remaining` (осталось запросов в текущем окне) и
`X-RateLimit-Reset` (unix-время сброса окна) — интеграции рекомендуется
ориентироваться на них, а не хардкодить значения из документации.

## Повышение лимитов
Для аккаунтов с оборотом от 5 000 000 ₽ в месяц лимиты повышаются
автоматически до 300 req/sec на чтение и 100 req/sec на запись без
дополнительного обращения в поддержку. Индивидуальное повышение сверх этого
— через api-support@finpay.ru с обоснованием нагрузки.

## Поведение при превышении (429)
При превышении лимита возвращается `429 Too Many Requests` с заголовком
`Retry-After` (секунды до следующей попытки). Запросы, отклонённые по
`429`, не учитываются в статистике ошибок SLA — это ожидаемое поведение
защиты, а не сбой сервиса.

## Батчинг операций
Для сценариев массового создания платежей (например, выплаты по 1000
получателям) рекомендуется batch-эндпоинт `POST /v2/payouts/batch`,
который принимает до 500 записей в одном запросе и не учитывается в
rate limit как 500 отдельных запросов — только как один.
