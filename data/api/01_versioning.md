# Версионирование API FinPay

## Схема версионирования
Версия указывается в пути запроса: `https://api.finpay.ru/v1/...`,
`https://api.finpay.ru/v2/...`. Текущая актуальная версия — v2, выпущена
в марте 2025 года. Версия v1 поддерживается в режиме security-fix-only.

## Политика устаревания (deprecation)
После выпуска новой мажорной версии предыдущая поддерживается не менее
18 месяцев. За 6 месяцев до отключения версии всем интеграциям, всё ещё
использующим её (по логам обращений), рассылается уведомление на
технический email аккаунта и добавляется баннер в личном кабинете.

## Отличия v2 от v1
- В v2 суммы передаются в минимальных единицах валюты (копейках/центах)
  целым числом, а не строкой с плавающей точкой — устраняет ошибки округления.
- В v2 добавлено поле `idempotency_key` как обязательное для всех
  POST-запросов, создающих платёж.
- В v2 изменён формат ошибок: единая структура `{"error": {"code", "message",
  "details"}}` вместо разрозненных полей v1.

## Заголовок версии в ответе
Каждый ответ API содержит заголовок `X-API-Version` с версией, которая
фактически обработала запрос — полезно для отладки при использовании
прокси или кеширующих слоёв между интеграцией и FinPay.

## Миграция с v1 на v2
Официальный гайд по миграции — developers.finpay.ru/migration-v1-v2.
Ключевой момент: параллельный запуск (dual-write) на переходный период не
поддерживается — платёж должен создаваться только через одну версию API,
смешивание версий в рамках одного платежа приводит к ошибке `409 Conflict`.
