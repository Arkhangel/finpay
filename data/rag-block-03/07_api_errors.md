# Коды ошибок API и поддержка FinPay

## Основные коды
- `400` — неверный формат запроса; нужно проверить тело запроса на соответствие
  схеме.
- `401` — неверный или просроченный API-ключ; ключ нужно проверить в личном
  кабинете lk.finpay.ru.
- `402` — недостаточно средств на карте клиента или карта отклонена банком;
  это ошибка на стороне плательщика, а не интеграции.
- `422` — ошибка валидации параметров запроса; детали — в поле `errors` тела
  ответа.
- `429` — превышен лимит запросов (100 req/sec на аккаунт); нужно реализовать
  retry с задержкой.
- `500` / `502` / `503` — ошибка на стороне FinPay; перед повтором стоит
  проверить status.finpay.ru — возможно, идёт плановое обслуживание.

## Обработка 429 (rate limit)
Рекомендуемый паттерн — exponential backoff: первая повторная попытка через
~1 секунду, дальше задержка удваивается, максимум 3–5 попыток. В Python для
этого удобны библиотеки `tenacity` или `backoff` — не нужно реализовывать
задержки вручную через `time.sleep` в проде.

## Отличие 401 от 402
Частая путаница в поддержке: `401` — проблема с самим API-ключом (авторизация
интеграции), а `402` — проблема с оплатой конкретного клиента (недостаточно
средств/отказ банка). Смена API-ключа не поможет при `402`.

## Куда обращаться
- api-support@finpay.ru — вопросы по интеграции и API, ответ в течение 4 часов
  в рабочие дни (пн-пт 9:00-21:00 МСК, сб 10:00-18:00 МСК).
- support@finpay.ru или чат в личном кабинете — общие вопросы по аккаунту,
  тарифам, возвратам.

## Статус системы
Перед обращением в поддержку по поводу ошибок `500`/`502`/`503` стоит сначала
проверить status.finpay.ru — там публикуется состояние компонентов (API,
checkout, dashboard, payments, payouts) в реальном времени. Если инцидент уже
зафиксирован там, отдельно писать не нужно — обновления публикуются на той же
странице.

## SLA по инцидентам
- Полная недоступность API: реакция в течение 30 минут, обновления статуса
  каждый час до устранения.
- Деградация отдельного компонента (например, только checkout): реакция в
  течение 2 часов в рабочее время поддержки.
- Некритичные баги (не блокирующие оплату): в порядке общей очереди, целевой
  срок ответа — до 4 часов в рабочие дни.
