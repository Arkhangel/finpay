# Типы событий вебхуков FinPay

## Платёжные события
- `payment.succeeded` — платёж успешно проведён, средства зарезервированы.
- `payment.failed` — платёж отклонён (банком, антифродом или по таймауту).
- `payment.pending` — платёж в обработке (актуально для СБП и рассрочки).
- `payment.refunded` — платёж полностью возвращён.
- `payment.partially_refunded` — платёж возвращён частично.

## События выплат
- `payout.created` — заявка на вывод создана.
- `payout.succeeded` — средства зачислены на расчётный счёт мерчанта.
- `payout.failed` — вывод не прошёл (неверные реквизиты, блокировка счёта).

## События подписок (рекуррентные платежи)
- `subscription.charged` — успешное списание по подписке.
- `subscription.charge_failed` — списание не удалось, доступна повторная
  попытка через 3 дня по умолчанию.
- `subscription.cancelled` — подписка отменена пользователем или мерчантом.

## Комплаенс-события
- `merchant.verification_required` — требуется донабор документов для
  верификации юрлица.
- `merchant.blocked` — аккаунт заблокирован службой комплаенса, доступ к
  выводу средств приостановлен до выяснения обстоятельств.

## Дублирование событий
Одно и то же событие теоретически может быть доставлено более одного раза
(например, из-за ретрая на стороне FinPay при неоднозначном ответе
получателя). Каждое событие содержит уникальный `event_id` — обработчик
должен сверяться с ранее обработанными `event_id` и игнорировать повторы.
