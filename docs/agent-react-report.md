# Блок 6.2 — ReAct-агент с self-reflection: сравнение с baseline

`app/services/agent_react.py` — управляемая версия наивного `agent_naive.py`
(Б6.1, оставлен без изменений как baseline): `max_iterations`/
`timeout_per_iteration_sec` вместо голого `for`-цикла, self-reflection
(critic-вызов после каждой tool observation, лимит ревизий 2/запуск, счётчик
не сбрасывается), строгие JSON Schema инструментов (`additionalProperties:
false`, все параметры в `required`, описания отвечают на 4 вопроса: что
делает / когда вызывать / что значат параметры / что возвращает).

**Отклонение от задания**: модели — `settings.openai.model`
(Groq `openai/gpt-oss-120b`) вместо `gpt-5.4-mini`/`gpt-5.4` — тот же сдвиг
"Groq вместо OpenAI", что и во всём проекте. Критик — `settings.eval.judge_model`
(`openai/gpt-oss-20b`), уже играющая роль независимого судьи в Б5.6 — здесь
естественно переиспользована как "младшая, отдельная от продакшена" модель
для дешёвой роли critic. `model_premium` (эскалация после REVISE) по
умолчанию совпадает с `model_main` — на бесплатном Groq tier модели мощнее
продакшена под рукой нет; параметр управляемый (можно передать другую
модель), но по умолчанию не расширяет реальные возможности агента —
честно фиксируем это как ограничение окружения, а не как выдуманную
"премиум"-модель.

## Наблюдения

1. **Timeout может сработать из-за холодного старта тула, а не LLM.** Первый
   запуск `search_knowledge_base` в свежем процессе (загрузка
   HuggingFace-эмбеддингов + re-ranker) занимал 10–17 сек сам по себе — этого
   достаточно, чтобы в одиночку исчерпать `timeout_per_iteration_sec=10`
   ещё до генерации ответа моделью. Обнаружено эмпирически (первый прогон
   задачи 1 упал с `"error": "Timeout"` при латентности 10 990 мс,
   `docs/agent-react-traces` того прогона не сохранились — воспроизведено
   повторно с той же картиной). Исправлено на уровне сравнения: скрипт
   прогоняет "прогрев" `search_knowledge_base` для обоих агентов до замера.
   В проде это значит: таймаут на итерацию должен либо прогревать
   инфраструктуру retrieval заранее, либо не включать холодный старт тула в
   тот же бюджет времени, что и LLM-вызов — иначе агент будет ошибочно
   "падать по таймауту", хотя причина не в LLM.
2. **Найден и исправлен реальный краевой случай: пустой `content` без
   `tool_calls`.** На повторных прогонах задачи 3 модель иногда (замечено 1
   раз из ~5 запусков) отдавала ответ без вызова инструмента И с пустым
   `content=""` вместо реального текста или вызова `send_telegram_message`.
   Изначальная реализация (`if not message.tool_calls: return
   {"answer": message.content, ...}`) в этом случае молча возвращала бы
   `answer=""` как будто агент успешно завершил задачу. Исправлено: пустой
   `content` без tool_calls трактуется как "модель ничего не сделала" —
   агент дописывает в историю просьбу дать реальный ответ или вызвать
   инструмент и продолжает цикл в рамках `max_iterations` (тест —
   `test_empty_content_without_tool_call_does_not_finish_silently` в
   `tests/unit/test_agent_react.py`).
3. **Self-reflection ни разу не сработал (`REVISE`) на этих 5 задачах.** Все
   `observation` были чистыми и релевантными thought — critic всегда
   возвращал `OK`. Лимит ревизий (≤2, без сброса между итерациями) и то, что
   после исчерпания лимита critic больше не вызывается вовсе (не тратим
   вызовы впустую), проверены отдельно моками
   (`test_revision_counter_caps_and_never_resets_between_iterations`) — на
   этих 5 сценариях ценность reflection эмпирически не продемонстрирована,
   она скорее раскрылась бы на задачах с шумным/частично нерелевантным
   retrieval, которых среди обязательных 5 нет.
4. **Управляемость стоит токенов.** react тратит в 2–4× больше токенов на
   задачу (2 188 против 419 на задаче 1, 3 888 против 1 060 на задаче 3) —
   ожидаемая цена: отдельный critic-вызов после каждого observation
   (фактически удваивает число LLM-вызовов на шаг с инструментом) плюс более
   длинный системный промпт. На этих 5 задачах выигрыша в числе итераций
   react над naive не было (одинаковое число шагов везде) — governance-слой
   здесь не сократил путь к ответу, а добавил стоимость контроля.
5. **Хаотичная провокационная задача — оба агента справились без tool-вызова
   в этом прогоне**, в отличие от зафиксированного в Б6.1 прогона
   (`docs/agent-naive-traces/03_tool_hallucination.json`), где `agent_naive`
   на этой же формулировке ответил честно про отсутствие инструмента, но
   выдумал в тексте ответа несуществующий API-эндпоинт (`GET
   /v1/users/{user_id}/balance`) с примером JSON. В сегодняшнем повторном
   прогоне такой фабрикации не произошло ни у naive, ни у react (оба дали
   чистый честный отказ) — вариативность сэмплирования модели: это означает,
   что более строгий системный промпт react снижает, но не гарантированно
   устраняет контент-галлюцинации; на одном прогоне обоих агентов делать
   вывод "react надёжнее" по этому конкретному пункту нельзя — нужна была бы
   серия повторов, что не входило в объём 5 обязательных задач.
